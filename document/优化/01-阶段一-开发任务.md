# 阶段一开发任务：三层结构化记忆体系

> 制定日期：2026-10-16
> 来源：`优化任务书.md` 阶段一 + grill-me 决策会话（10 问全部闭合）
> 上游文档：`document/优化/优化任务书.md`
> 预计工期：约 1.5 周

## 0. 设计总纲（一句话版）

- **长期记忆存"世界的状态"，任务记忆存"过程中得到的教训"**——这是面试叙事的锚点。
- task 记忆是**暂存态**：子 agent 收尾写入 → 空闲时蒸馏进长期记忆 → 源文件删除。目录稳态接近清空。
- 全链路失败静默（与现有召回"失败即不召回"哲学一致），记忆子系统永远不阻塞主对话。

## 1. 分支决策记录（grill-me 定案）

### A. task 类型定位

| 决策点 | 定案 |
|---|---|
| 存储位置 | `./.tencoder/memory/tasks/` 独立子目录，frontmatter 仍用 `type: task` |
| 理由 | 蒸馏范围好圈定（扫目录即可）、体积监控好做（`du` 即可）、生命周期与长期记忆隔离 |
| 连带改动 | `ScanMemoryFiles` 多扫 tasks 子目录；`IsAutoMemPath` 认账 tasks 子目录（沙箱放行前提） |

### B. WhatNotToSave 改写（对应任务 1.5）

拆成两条规则：

1. **旧四类（user/feedback/project/reference）**：规则原样保留，ephemeral 细节仍不进。
2. **task 专属白名单**（新增段落），只允许存四样：
   - 踩坑/失败及**原因**（不是现象）
   - 恢复路径（"先查 X 再试 Y"这类动作序列）
   - 用户在任务中口头给出的、代码里找不到的约束
   - 任务结果对后续工作的影响（"改了 A 必须同步改 B"这类隐藏耦合）

   明确禁止：目标复述、动作流水账、代码 diff、文件路径清单（可从 git/代码状态推导）。

### C. 数据结构（对应任务 1.1）

四段结构（目标 → 动作序列摘要 → 踩坑/失败 + 恢复路径 → 结果）是**生成端检查清单**，不是模板段落：

- **目标**：压成一句话任务标识，进 frontmatter `description`（兼做检索关键词），不占正文；
- **动作序列摘要**：只保留改变结果的**转折点**，不是步骤流水账；
- **踩坑/失败 + 恢复路径**：正文主体，必填；
- **结果**：一句话 + 对后续工作的影响（隐藏耦合点）。

frontmatter 沿用现有格式（name/description/type），不新增状态字段——是否已蒸馏由"文件是否还在 tasks/ 目录"隐式表达。

### D. 收尾钩子（对应任务 1.2）

| 决策点 | 定案 |
|---|---|
| 挂点 | `internal/agents/subagent.go` 的 `taskMgr.SetCompleted(taskID, output)` 之后 |
| 内容生成 | **旁路轻量 LLM** 从 output 提取，注入式接口（抄 extractor 的 `SelectorFn` 模式），不新增包级依赖 |
| 执行方式 | fire-and-forget goroutine；`SetCompleted` 先行，提取+写文件异步；失败静默跳过 |
| 覆盖范围 | **只做子 agent 路径**（与简历口径"子任务同步"逐字对齐）；主 agent 不写 task 记忆，主任务的沉淀责任由 1.3 承担 |
| 理由 | 不污染子 agent 最终 output（那是给主 agent 消费的）；提取调用天然是轻量模型流量，预埋阶段五路由场景 |

### E. 空闲蒸馏（对应任务 1.3）

用户选定**空闲后台蒸馏**（任务书风险条原方案，否掉了惰性方案备选）。完整方案：

| 决策点 | 定案 |
|---|---|
| 空闲判定 | 主循环 `LoopComplete` 后 60 秒（可配置）无新用户输入即触发 |
| 并发保护 | 全局单飞：`sync.Mutex` + `TryLock`，上一轮未跑完则本轮直接跳过 |
| 沙箱对齐 | 写路径全部落在 `./.tencoder/memory/`（tasks 子目录归档 + 长期记忆更新），复用 `IsAutoMemPath` 放行 |
| LLM 客户端 | 注入式接口，复用当前会话轻量模型配置；失败静默，本轮放弃等下轮 |
| 蒸馏输入 | 待蒸馏 task 记忆全文 + 现有 project 级长期记忆**清单**（filename + description，不灌全文，控 token） |
| 蒸馏输出 | 结构化动作列表，仅四种：`create` / `update` / `merge` / `skip` |
| 源处置 | 动作执行成功 → **删除**对应 task 记忆文件；失败 → 保留待下轮重试。不设归档目录（归档只是把单调增长挪个地方；阶段一不需要审计回溯，取舍写进开发记录） |
| 堆积兜底 | tasks/ 超 20 条时下一轮强制触发蒸馏（不受 60s 窗口约束） |

"体积不单调增长"是结构性保证：task 记忆只减不增，长期记忆靠 update/merge/skip 控制膨胀，skip 顺手执行白名单。

### F. 召回（对应任务 1.4）

| 决策点 | 定案 |
|---|---|
| 准入 | task 记忆与四类一视同仁进 ≤5 槽位候选池，**不加硬配额** |
| 软引导 1 | selector 系统提示词补一句：task 类型 = 近期任务踩过的坑与恢复路径，续做/修复类查询优先考虑 |
| 软引导 2 | 生成端强制 description 以任务关键词开头（来自 C 的任务标识） |
| 兜底 | 20 条上限 + 空闲蒸馏保证 tasks/ 稳态清空，堆积只是瞬态 |

### G. 验收口径

**验收标准 1 场景——两段式埋坑**：

- **会话 A**：布置多子 agent 任务（如"给 internal/memory 加导出功能"），预埋隐藏坑（某测试文件有硬编码路径，子 agent 首次必撞，需失败后恢复）；
- **会话 B**：新开会话说"继续上次的活"；
- **通过判定（可量化）**：召回的 ≤5 条含那条教训记忆，且 agent 首轮动作明确绕坑（先改硬编码路径或先跑该测试）。

一石三鸟：同时验证 1.2 落盘（A 会话有 task 文件）、1.4 召回（B 会话选中）、蒸馏不干扰暂存态召回（蒸馏后走长期记忆召回同样算过）。

**验收标准 3——token 开销**：提取调用与蒸馏调用各打一行最简日志（档位、输入/输出 token、耗时），字段对齐阶段五 5.5 埋点，按"每子任务平均新增 token"和"每轮蒸馏平均 token"两个口径出数。不上看板。

## 2. 开发任务分解（落地顺序）

> 顺序原则：规则先立（1.5 → 生成才有约束）→ 数据结构 → 写入 → 召回（先打通暂存态，验收场景即可跑）→ 蒸馏闭环收尾。

| 序 | 任务 | 落点 | 关键点 |
|---|---|---|---|
| T1 | WhatNotToSave 拆两条 + task 类型定义与白名单提示词 | `internal/memory/memory_types.go` | 新增 `TypeTask`；`TypesSectionDualPath` / `TypesSectionIndividual` 补 task 段落；`WhatNotToSaveSection` 拆分 |
| T2 | tasks 子目录识别 | `internal/memory/paths.go`、`memory_scan.go` | `IsAutoMemPath` 认账 `tasks/`；`ScanMemoryFiles` 支持扫子目录 |
| T3 | 收尾钩子 + 旁路提取 | 新增 `internal/memory/task_write.go`；钩子挂 `internal/agents/subagent.go` | 注入式 LLM 接口；fire-and-forget；失败静默；落盘到 `tasks/` |
| T4 | 召回接入 | `internal/memory/find_relevant_memories.go` | selector 提示词补 task 说明；无硬配额 |
| T5 | 空闲蒸馏 | 新增 `internal/memory/task_consolidate.go`；触发挂主循环事件 | 60s 空闲判定、TryLock 单飞、四动作结构化输出、删源、20 条兜底 |
| T6 | token 日志 | T3/T5 调用处 | 单行日志：档位、输入/输出 token、耗时；字段对齐阶段五 5.5 |
| T7 | 验收执行 | 人工构造场景 | 两段式埋坑场景跑通 + 三条验收标准逐条出证据 |

## 3. 验收标准（自任务书，口径已定）

1. 同一任务跨会话续做，agent 能召回上次的失败教训（两段式埋坑场景，判定见 G）；
2. 蒸馏合并后记忆文件数量与体积不单调增长（结构性保证 + 实测佐证）；
3. 记录每任务新增 token 开销（"每子任务均摊 token"两个口径出数）。

## 4. 风险与对策

| 风险 | 对策 |
|---|---|
| 空闲蒸馏引入项目第一条后台并发管线 | TryLock 单飞 + 失败静默 + 写路径全部在 IsAutoMemPath 放行范围内；开发记录里单列"并发保护"小节 |
| Ctrl/C 退出丢蒸馏机会 | 可接受：task 记忆仍在 tasks/，下次空闲触发补蒸；不追求退出时同步蒸馏（SIGINT 语义不可靠） |
| task 记忆堆积挤占召回槽位 | 20 条强制蒸馏兜底 + 暂存态短生命周期，瞬态可接受 |
| 提取 LLM 幻觉写入垃圾 | 白名单四样硬约束写进提取提示词；skip 动作兜住可推导内容 |
