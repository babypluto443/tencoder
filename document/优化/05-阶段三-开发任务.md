## 0. 设计总纲（一句话版）

- **驱逐策略的第一约束不是 LRU 本身，而是 prompt cache 经济学**——现有设计连工具结果替换都逐字节冻结来保 cache 前缀，驱逐必须摊销为低频批量事件，不能逐轮碎敲。
- 摘要中间层是现有 Layer 1 spill 机制的 **preview 位升级**：全文照旧落盘可回读，上下文里从"机械截断预览"换成"知道任务目标的结构化摘要"。
- 全链路失败回退现状（驱逐失败=不逐、摘要失败=保留 preview），行为只会更好不会更坏。

## 1. 现状事实（代码摸底结论）

- MCP 工具全部 `ShouldDefer()=true`（`internal/mcp/mcp.go` 的 `MCPToolWrapper`）；`Registry.MarkDiscovered` 之后 schema **永久**进入 `GetAllSchemas`——只装不卸，3.1 补的就是这个洞。
- `toolresult.Apply`（Layer 1）：单结果 >50KB / 消息聚合 >200KB 触发 spill 落盘 `.tencoder/tool_results/`，上下文留 preview；决策通过 `ContentReplacementState` **冻结逐字节回放**，保 prompt cache 前缀稳定。
- `deferred_benchmark_test.go` 已有 realisticMCPTool + 50 deferred 工具的 benchmark，百级场景直接扩展。

## 2. 分支决策记录（grill-me 定案）

### A. LRU 驱逐：阈值批量驱逐（3.1）

| 决策点 | 定案 |
|---|---|
| 触发 | discovered（已装载 schema）集合 **>40** 触发一轮驱逐，砍回 **25**（均可配置） |
| 批量 | 一次打包逐掉最久未用的一批，**不逐轮碎敲**——cache 失效摊销为低频批量事件（百级工具长会话预计整个会话仅两三次） |
| LRU 时钟 | 以工具**真正 Execute** 的时间为准；只被 ToolSearch 发现但从未调用的按**发现时间**计（占坑无产出，优先逐） |
| 豁免 | 会话内 Execute ≥2 次的活跃工具不逐（反复装逐纯属浪费 ToolSearch 往返） |
| 驱逐语义 | **回池**：被逐工具回到 deferred 池，`GetDeferredToolNames` 重新列出，ToolSearch 可再发现——功能无损，只多一次 select 往返 |
| 落点 | `internal/tools`（Registry 加驱逐）+ `internal/agent/agent.go`（每轮迭代头部检查阈值） |

### B. 工具结果摘要：LLM 摘要 + 冻结（3.2）

| 决策点 | 定案 |
|---|---|
| 位置 | Layer 1 spill 的 **preview 位升级**：`toolresult.Apply` 生成替换内容时，调旁路轻量模型生成结构化摘要 |
| 时序 | **同步**——异步来不及（摘要必须赶在下一轮 prompt 组装前进上下文）；spill 是罕见事件（50KB 阈值挡着），单次 1~3s 可接受 |
| 摘要内容 | 关键数值、错误信息、结论；**带任务上下文**（知道哪段对当前任务重要——这是相对规则摘要的核心优势） |
| 冻结 | 摘要随决策一起进 `ContentReplacementState` 逐字节回放，cache 前缀依然稳定 |
| 失败回退 | 摘要调用失败 → 回退现有机械 preview，行为不劣于现状 |
| 兜底 | 全文仍在落盘文件（`.tencoder/tool_results/`），agent 可随时 ReadFile 回读——摘要幻觉丢细节由这条路兜住 |
| 落点 | `internal/toolresult`（preview 生成处）+ 注入式旁路接口（阶段一 `TaskExtractorFn` 同款模式） |

### C. 回归判定：埋约束 + 终点 checklist（3.3）

- **场景**：构造天然 40+ 轮的任务（10+ 文件修改、中途跑测试/看日志/翻配置），**预埋 3 个必须遵守的约束**（如"X 文件不能动 / 必须用 Y 库 / 最后跑 W 命令"），确保中途至少触发一次 Layer 2 压缩；
- **判定**（旁路强模型，同阶段二判定模式）：三组 checklist——
  1. **约束遵守**：3 个预埋约束在最终交付中全部遵守（违反 = 上下文丢失的直接证据）；
  2. **任务完成度**：目标改动完整覆盖；
  3. **无幻觉引用**：最终交付引用的文件/函数真实存在（压缩后模型常"记得"已不存在的上下文）；
- 跑 3 次取结果。不用中途回忆探针——探针会改变对话轨迹，测的就不是原任务的压缩行为了。

### D/E. 度量口径（我直接拍）

- **百级工具场景**：扩展 `deferred_benchmark_test.go` 至 120 个 realistic 工具；
- **token 口径**：`GetAllSchemas` 序列化后的**字符数**（可复现；面试表述"字符数，token 按 ÷4 估算"并标注估算方法）；
- **同义工具混淆**（验收 3）：构造 5 组描述相近的工具，混合驱逐状态，验证：(a) 驱逐后 ToolSearch 能正确重发现；(b) 工具选择准确率与不驱逐基线一致。

## 3. 开发任务分解（落地顺序）

| 序 | 任务 | 落点 | 关键点 |
|---|---|---|---|
| T1 | Registry 驱逐能力 | `internal/tools/tool.go` | `EvictDiscovered(keep int, exempt map[string]bool)`；LRU 时钟记录（Execute/发现时间）；驱逐回池 |
| T2 | 活跃度跟踪 | `internal/tools` + 工具执行路径 | Execute 时打时间戳与次数；豁免集维护 |
| T3 | 主循环阈值检查 | `internal/agent/agent.go` | 每轮迭代头部检查 discovered 上限，超限触发批量驱逐；驱逐事件透出给 TUI |
| T4 | 摘要中间层 | `internal/toolresult` | preview 位升级为旁路 LLM 摘要；摘要冻结进回放；失败回退 |
| T5 | 配置项 | `internal/config` | 驱逐上限/低水位、摘要开关与轻量模型档位 |
| T6 | 百级工具 benchmark 扩展 | `internal/tools/deferred_benchmark_test.go` | 120 工具；驱逐前后常驻 schema 字符数对比输出 |
| T7 | 同义混淆测试 | 新增测试场景 | 5 组近义工具，驱逐后重发现 + 选择准确率验证 |
| T8 | 数十轮回归评测 | 复用 `cmd/tencoder-eval` | 40+ 轮场景 + 3 约束预埋 + 终点 checklist 自动判定，跑 3 次 |

## 4. 验收标准（自任务书，口径已定）

1. 百级工具场景下常驻 schema 字符数相比现状进一步下降（85% 基础上的**增量实测数**：现状 discovered 永不驱逐 vs 阈值批量驱逐，同场景对比）；
2. 数十轮连续会话回归通过：3 组 checklist 全部通过、跑 3 次无失败；
3. 工具选择准确率不因动态驱逐而下降（5 组同义工具混淆场景，驱逐态与全量态选择一致）。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 驱逐击穿 prompt cache | 阈值批量摊销；豁免活跃工具；预计会话内仅两三次失效，开发记录中实测 cache 命中率佐证 |
| 摘要幻觉丢关键细节 | 全文落盘可 ReadFile 回读；摘要提示词要求"数值与错误信息逐字保留"；失败回退 preview |
| 摘要同步阻塞 | 仅 spill 罕见事件触发；轻量模型；单次 1~3s 开发记录中实测 |
| 驱逐后工具选择变差 | 同义混淆测试（T7）前置验证；驱逐回池保证任何工具都可通过 ToolSearch 重新发现 |
| 回归场景不稳定（LLM 随机性） | 3 约束客观可判；跑 3 次；场景任务收敛（无开放性设计决策） |
