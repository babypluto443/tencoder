## 阶段一：三层结构化记忆体系（对应简历卖点①，约 1.5 周）

**目标**：落地"工作记忆 / 短期任务记忆 / 长期项目记忆"三层体系，解决上下文失效与重复踩坑。

| # | 任务 | 落点 |
|---|---|---|
| 1.1 | 定义短期任务记忆（episodic）数据结构：`目标 → 动作序列摘要 → 踩坑/失败 + 恢复路径 → 结果`，新增 `task` 类型 | `internal/memory/memory_types.go` |
| 1.2 | **子任务完成后同步短期记忆**：子 agent 收尾钩子结构化落盘一条任务记忆 | 新增 `internal/memory/task_write.go`，钩子挂多 agent 协作收尾处 |
| 1.3 | **任务结束沉淀长期项目记忆**：会话结束/空闲时用旁路 LLM 把任务记忆去重、合并进 project 级记忆 | 新增 `internal/memory/task_consolidate.go` |
| 1.4 | **跨会话复用**：任务记忆进入现有 ≤5 条召回候选池 | `internal/memory/find_relevant_memories.go` |
| 1.5 | 更新 WhatNotToSave 规则，任务记忆不存"从代码状态推得出来"的内容 | `memory_types.go` 提示词 |

说明：工作记忆 = 现有 `conversation` + 两层压缩，不动。

**验收标准**：
1. 同一任务跨会话续做，agent 能召回上次的失败教训（人工构造 1 个场景验证）；
2. 蒸馏合并后记忆文件数量与体积不单调增长；
3. 记录每任务新增 token 开销。

**风险**：空闲蒸馏引入后台并发，需与沙箱放行逻辑（`IsAutoMemPath`）对齐。

## 阶段二：子任务检查点与独立反思节点（对应简历卖点②，约 1.5 周）

**目标**：落地简历承诺的偏移率改善——**目标偏移占比从 32% 降至 11%**。

| # | 任务 | 落点 |
|---|---|---|
| 2.1 | 独立反思节点：旁路 LLM 以第三人称视角校验"当前路径/轨迹 vs 任务目标"一致性，输出 yes/no，采 3 次投票防抖 | 新增 `internal/agent/reflection.go` |
| 2.2 | **触发时机按简历四个事件**：定位完成、补丁生成、测试失败、异常回调时触发检查（周期性检查只作兜底，可配置关闭） | 主循环事件总线 |
| 2.3 | 偏移处置：判 No → `AddSystemReminder` 注入目标重申；连续 K=3 次 No → 中断重规划 | `internal/conversation` + 主循环 |
| 2.4 | 偏移事件写入短期任务记忆（对接 1.2 钩子） | 复用阶段一 |
| 2.5 | 反思节点固定走轻量模型（为阶段五准备路由流量） | 对接阶段五 |

**偏移率口径（按简历场景定义，面试必问）**：
- **基准场景**：三文件协同还原测试任务（agent 需同时正确修改三个文件）；
- **偏移定义**：最终交付未覆盖三个文件中任一文件的目标改动，或引入了任务目标之外的改动，即记为偏移；
- **偏移占比** = 偏移任务数 / 总任务数；
- **目标**：关闭反思基线约 32% → 开启反思后 ≤11%；两组各跑 ≥10 次取均值。

**验收标准**：
1. 上述口径下偏移占比达成 32%→11%；
2. 反思节点自身 token 开销可见且可控（事件驱动，非每步触发）；
3. 四个触发事件均有至少一次真实触发记录。

## 阶段三：MCP 工具治理增强（对应简历卖点③④，约 1 周）

**目标**：在已有"延迟加载 85%"基础上增强长会话工具治理，并保证两层压缩兼容。

| # | 任务 | 落点 |
|---|---|---|
| 3.1 | 动态工具装载/驱逐：长会话中按任务动态加载工具 schema，LRU 驱逐闲置工具 | `internal/mcp`（在现有延迟加载上加生命周期管理） |
| 3.2 | 工具结果压缩：超长工具输出先摘要再进上下文 | 新增工具结果中间层 |
| 3.3 | 两层上下文压缩回归：数十轮连续会话无关键上下文丢失 | 现有压缩模块回归测试 |

**验收标准**：
1. 百级工具场景下常驻 schema token 相比现状进一步下降（在 85% 基础上的增量，需给出实测数）;
2. 数十轮连续会话回归通过，关键上下文无丢失；
3. 工具选择准确率不因动态驱逐而下降（构造同义工具混淆场景验证）。

## 阶段四：多 Agent 协作完善 + 跨项目修改（对应简历卖点⑥⑦⑧，约 1.5 周）

**目标**：补齐"跨 Agent 进度接口 + 文件级权限审计与写入确认"，并新增跨项目管理能力。

| # | 任务 | 落点 |
|---|---|---|
| 4.1 | 跨 Agent 进度接口：协调 agent 汇总各子 agent 进度，走结构化进度消息而非全文粘贴 | 对接 05 号文档的多 agent 模块 |
| 4.2 | 文件级权限审计与写入确认：五层沙箱上补审计日志（谁在何时对哪个文件做了什么写操作）+ 写前确认钩子 | 权限模块（04 号文档对应代码） |
| 4.3 | 项目注册表：声明多项目路径与级别（`可写` / `只读参考`） | 新增 `internal/workspace` |
| 4.4 | 沙箱加 workspace 维度：子 agent 绑定单 workspace，写操作按项目级别校验 | 权限模块 |
| 4.5 | 可写项目用 git worktree 隔离，跨项目写走显式审批链 | 新增 worktree 管理命令 |

**验收标准**：
1. 跨文件重构任务耗时保持单 Agent 对比约 60% 的优势不回退；
2. 演示"一个对话窗口内同时修改两个项目且互不污染"；
3. 只读项目的任何写尝试被拒绝，且审计日志有完整记录；
4. 所有写操作在审计日志中可追溯（文件级）。

**风险**：worktree 共享 .git 存在 hook 注入面——worktree 是冲突边界不是安全边界，跨项目安全靠沙箱 + 审批链，面试主动讲这个 trade-off。

## 阶段五：任务分级多模型动态路由（对应简历卖点⑤，约 1.5 周）

**目标**：落地简历承诺——**推理成本降低约 45%，平均响应延迟缩短约 31%**，成功率不回退。

| # | 任务 | 落点 |
|---|---|---|
| 5.1 | 模型分级抽象：strong/light 两档，调用方声明任务类型 | 新增 `internal/llm/router.go` |
| 5.2 | 规则路由 v1：任务类型 + 预估工具调用预算 + 上下文大小三信号决定档位 | 同上 |
| 5.3 | 接入路由点（与简历口径一致）：文件读取、日志摘要、格式校验、记忆检索 → 轻量模型；补丁/代码生成、架构判断、多文件冲突合并、跨项目改动 → 强模型 | 各调用点改造 |
| 5.4 | 级联升级：轻量模型输出过不了质量门禁（编译/测试/格式校验）→ 自动升级强模型重试 | `router.go` + 质量门禁 |
| 5.5 | 调用埋点：记录档位、token、时延、是否升级（供统计简历数字，不建看板） | 调用日志 |

**验收标准**：
1. 在自建多级路由评测子集上，推理成本降低 ≥45%、平均响应延迟缩短 ≥31%（与全强模型同任务对比，对照数据取自阶段二~四期间积累的调用日志）；
2. 任务成功率不回退；
3. 轻量档占比 ≥60% 时成功率仍不回退。

**依赖**：阶段二（反思节点轻量流量）、阶段四（跨项目改动等强模型场景）。
