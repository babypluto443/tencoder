> 制定日期：2026-10-16

> 上游文档：`document/优化/优化任务书.md`；对应简历卖点⑤（成本 -45% / 延迟 -31%）
> 预计工期：约 1.5 周
> 编号说明：`04/06/08-` 分别预留给阶段二/三/四开发记录，本篇为 `09-`

## 0. 设计总纲（一句话版）

- **声明式路由，不搞自动分类**——自动分类自己要花一次 LLM 调用（为省钱先花钱），规则推断不可靠；调用方最清楚自己在干什么活。
- **门禁要便宜，升级要续作**——门禁三件套秒级完成保住 -31% 延迟；续作修复避免重做的 token 翻倍。
- **数字全部重测**——不引用历史日志当对照（那是混合档位，口径不成立），与阶段二/四的"实测不引用"哲学统一。

## 1. 现状事实（代码摸底结论）

- `internal/llm/model_resolver.go`：haiku/sonnet/opus 短名 → 真实模型 ID，闭包克隆 base 配置只改 Model 字段；
- `AgentTool.selectClient` 已按 `spec.Model` 给子 agent 切模型（explore 已是 haiku）——router 在此处接管即可；
- 旁路调用（记忆 selector / 任务提取 / 蒸馏 / 反思 / 工具结果摘要）均为注入式 fn，装配在 TUI 侧——router 收口这些装配点；
- 主循环固定会话主模型（strong），补丁生成天然走强档；
- 阶段一~四的单行日志已对齐 5.5 埋点字段（档位/输入输出 token/耗时），缺升级标记。

## 2. 分支决策记录（grill-me 定案）

### A. 管辖范围与 API（5.1/5.2）

| 决策点 | 定案 |
|---|---|
| 接入面 1 | **旁路调用收口**：五个旁路装配点统一改走 router（基线 light 档） |
| 接入面 2 | **子 agent spawn**：`selectClient` 改为问 router——按声明 TaskClass + spec 裁决 |
| 不接入 | **主循环不路由**（会话主模型即 strong；路由主循环质量风险直接落在交付物上） |
| API | `Resolve(class TaskClass, hints RouteHints) (llm.Client, Tier, routeReason)` |
| TaskClass 枚举 | memory_recall / log_summary / format_check / explore / patch_gen / arch_decision / conflict_merge / cross_project |
| 三信号裁决 | **声明类型**定基线档（前四类 → light，后四类 → strong）+ **预估工具调用预算**（超预算升档）+ **上下文大小**（超阈值整体升一档——巨大上下文下轻模型质量衰减明显） |
| 否掉的方案 | 自动分类（LLM 自判档位 = 为省钱先花钱；关键词规则 = 不可靠且面试难自圆其说） |

### B. 级联升级（5.4）

| 决策点 | 定案 |
|---|---|
| 门禁 | **便宜三件套**：`go build` + `go vet` + `gofmt -l`（秒级）；完整测试**不进门禁**——留给主 agent 正常工具循环（主 agent 发现测试失败自然反馈，那是 agent 行为不是路由职责） |
| 触发范围 | 仅"声明为代码生成类且走了 light 档"的子 agent 完成时触发门禁 |
| 重试形态 | **续作修复**：轻量产出（diff）+ 门禁失败信息作为输入，spawn 强模型只做修复——比从零重做便宜得多 |
| 防循环 | 每任务最多升级 **1 次**；升级后仍不过门禁 → 返回失败给主 agent，不重试 |
| 否掉的方案 | 全量测试门禁（分钟级，吃光 -31% 延迟）+ 丢弃重做（token 翻倍吃掉成本优势） |

### C. 对照数据口径（5.5 / 验收 1，修订任务书）

**任务书原文有坑**："对照数据取自阶段二~四积累的调用日志"——但那些日志里反思/提取/蒸馏/摘要**本来就是 light 档**（各阶段落地时已绑定轻量模型），是混合档位数据，不是"全强模型"对照。引用它 = 高估降幅 + 口径对不上。

修订为：**重测对照**——

- 对照组：路由关闭（router 加 `disabled` 开关，所有调用强制 strong），全子集批跑；
- 实验组：路由开启，同子集批跑；
- 同任务、同模型配置；历史日志降级为趋势佐证（展示各阶段旁路流量演进，进开发记录不进简历）。

### D/E. 评测子集与统计口径（直接拍板）

- **评测子集（≈15 任务）**：轻量类（记忆检索问答 ×3、日志摘要 ×2、格式校验 ×2、代码探索 ×3）+ 强类（三文件协同还原 ×2、跨项目改动 ×2、多文件冲突合并 ×1）——复用阶段二/四已建场景，新增轻量类；
- **成本口径**：`Σ(token × 该档位单价)`——**不是纯 token 数**（light 单价远低于 strong，纯 token 数会大幅低估降幅）；
- **延迟口径**：任务端到端墙钟时间均值；
- **单列指标**：轻量档占比（验证 ≥60% 目标）、升级率（过门禁失败率）、升级后成功率。

## 3. 开发任务分解（落地顺序）

| 序 | 任务 | 落点 | 关键点 |
|---|---|---|---|
| T1 | router 核心 | 新增 `internal/llm/router.go` | TaskClass 枚举；三信号裁决；`Resolve` API；disabled 开关；routeReason 输出 |
| T2 | 旁路装配收口 | TUI 装配处（memory/反思/摘要/提取/蒸馏） | 五个注入点改走 router；埋点字段补齐 |
| T3 | 子 agent 接入 | `internal/agents/agent_tool.go` selectClient | spec.Model 与 TaskClass 声明合并裁决；spec 加 taskClass 字段 |
| T4 | 门禁三件套 | 新增 `internal/llm/qualitygate.go`（或 agent 包） | build/vet/gofmt 封装；超时控制；结果结构化 |
| T5 | 续作升级链 | `internal/agents` | 门禁失败 → 强模型续作 spawn（diff+失败信息输入）；最多 1 次；升级标记进埋点 |
| T6 | 评测子集 | 复用 `cmd/tencoder-eval` | ≈15 任务定义（复用阶段二/四场景 + 新增轻量类）；自动成功率判定 |
| T7 | 对照批跑与统计 | 评测脚本 | 两组全子集批跑；成本 = Σ token×单价；延迟墙钟；占比/升级率单列 |
| T8 | 简历数字产出 | 汇总报告 | ≥45% 成本降、≥31% 延迟降、成功率不回退、light 占比 ≥60% 四个数各附批跑证据 |

## 4. 验收标准（自任务书，口径已定）

1. 自建评测子集上，推理成本降 ≥45%、平均延迟缩短 ≥31%（**重测对照**：全强 vs 路由，两组各一轮全子集）；
2. 任务成功率不回退（两组成功率对比，路由组 ≥ 对照组 - 0）；
3. 轻量档占比 ≥60% 时成功率仍不回退（占比与成功率同批跑数据交叉验证）。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 轻模型质量崩导致成功率回退 | 级联升级兜底；门禁前置拦截；TaskClass 基线档划分保守（拿不准就 strong） |
| 门禁误放行（编译过但逻辑错） | 明确定位：门禁是"语法层安全网"，逻辑正确性由主 agent 测试循环负责——面试主动讲这个分层 |
| 升级续作引入新 bug | 续作输入包含完整轻量 diff + 结构化失败信息；升级后同样过门禁 |
| 三信号阈值拍脑袋 | 阈值进配置；批跑时可对 1~2 组阈值做小规模敏感性检查 |
| 批跑成本（30+ 任务次 × 双组） | 轻量类任务本身便宜；强类复用阶段二/四已验证场景；子集刻意控制在 ≈15 |
